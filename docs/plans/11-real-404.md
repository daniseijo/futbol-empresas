# 11 · A real 404

## Why

`/partidos/1`, `/equipos/no-existe` or `/jugadores/0` answer **200** with the "FUERA DE JUEGO" page. Unknown routes
(`/no-existe`) already answer 404. Next adds `<meta name="robots" content="noindex">`, so search engines do not index
them, but link checkers, previews and monitoring see a success, and Google may report them as "soft 404".

The cause, from `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/not-found.md`: the page shell
streams before the data is read, and `notFound()` runs inside the `<Suspense>` boundary (`MatchContent`,
`TeamHeader` in `equipos/[slug]/layout.tsx`, `PlayerContent`…), when the `200` has already been sent. "Calling
`notFound()` before streaming starts returns a `404`… A request-time check can run in Proxy before the page renders."

## Options

1. **Check existence before the `<Suspense>`**, in the page component itself, with a cheap cached query
   (`matchExists(id)`, `teamSlugExists(slug)`, `playerExists(id)` in `src/lib/data.ts`, `"use cache"` +
   `cacheTag(DATA_TAG)`). Read the Cache Components docs first: awaiting data outside `<Suspense>` blocks the static
   shell, and Next may refuse it at build time ("uncached data outside Suspense") unless it is cached. Check whether
   it costs the instant navigation the skeletons give today (`next-partial-prefetching-adoption` and the Partial
   Prefetching docs).
2. **Proxy** (`src/proxy.ts`, see `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md`):
   look the id up and rewrite to a 404. That adds a database round trip to every request of those routes, and
   Proxy may not be able to use `"use cache"`: probably worse.
3. **Known ids in a static set**: `generateStaticParams` already prerenders some pages; a page that hits
   `notFound()` while prerendering stays static and serves a 404. Does not cover ids created later.

Try option 1 on `/partidos/[id]` first, measure (build output, `curl -w "%{http_code}"`, how fast a client
navigation shows the skeleton), and only roll it out to teams, players, venues, competitions and day pages if it does
not slow navigation down. If no option keeps navigation instant, write down why in `docs/plan.md` and close the item:
the `noindex` already covers SEO.

Also look at the dev-only "cannot have a negative time stamp" error in `performance.measure` on a first 404 load:
confirm it comes from React/Next (stack trace), and if there is an upstream issue, link it in `docs/plan.md`.

## Done when

- `curl -s -o /dev/null -w "%{http_code}" <prod>/partidos/1` prints 404, and the same for a bad team slug and player
  id, while real pages still answer 200.
- Client navigation to a real match still shows its skeleton immediately.
